# MG Group: SEO, sharing previews and icons

Implementation date: 7 October 2026. Canonical URL: <https://marketing.parkskazka.ru/mg-group/>.

## Crawlable content and metadata

The complete Arabic-first, English-second presentation and its metadata are included in static HTML. No JavaScript execution, authentication, cookies or remote image API is required to obtain the title, description, previews, icons or structured data. Main navigation uses real fragment links while retaining presentation navigation.

`src/data/site-metadata.ts` owns the title, bilingual description, canonical URL, preview alt text and JSON-LD. `src/app/layout.tsx` defines Open Graph website metadata, Arabic locale and English alternate locale, Twitter large-image cards, robots/Googlebot image and snippet permissions, authorship, application name, referrer policy, format detection, browser colors and icon links. Charset and responsive viewport are rendered by Next.js; zoom remains enabled.

JSON-LD describes the Organization, WebSite, WebPage, primary ImageObject and four visible service areas. The Moscow address and Omani contact are supplied by the owner. The 64 technical specialists are not asserted to be the company's total employee count. No invented reviews, prices, social accounts, legal registration identifiers, founding date or completed-construction claims are included.

One bilingual page has one canonical URL and one sitemap entry. There are no separate language URLs, so no fictional `hreflang` destinations. Headings and body language blocks remain explicit. No obsolete `keywords`, `revisit-after`, location coordinates, unrelated article/video metadata, fabricated verification tokens, Facebook app IDs or Twitter handles are emitted. These would not create additional search or messenger support.

`public/sitemap.xml` contains the actual page modification date. Only the origin-root `/robots.txt` governs crawler access. `ops/register-sitemap.py` appends the MG sitemap there with an expected-hash guard, recoverable backup and atomic replacement, preserving the existing Salalah entry and other directives. A project-subdirectory robots file would not govern crawling and is not created.

## Generated preview package

| File under `public/social/` | Size | Purpose |
| --- | --- | --- |
| `mg-group-og-v1.jpg` | 1200 × 630 | Primary Open Graph preview |
| `mg-group-card-v1.jpg` | 1200 × 600 | Twitter/X large-image card |
| `mg-group-square-v1.jpg` | 1200 × 1200 | Secondary OG square image and manual sharing asset |
| `park-concept-v1.jpg` | 1727 × 911 | Optimized generated photographic source |

The primary image is declared first with absolute HTTPS URL, secure URL, MIME type, dimensions and alt text. Final JPEGs are under 350 KB, use stable versioned names and require no client-side rendering. A scraper may select only the first image; the square alternative is not a promise of device-specific automatic art direction.

The scene was created using the built-in `image_gen` tool in new-image mode. Generation brief: a photorealistic blue-hour amusement park, a central white observation wheel, warm amber illumination, coaster on the left, palms and coastal horizon on the right, a subtle precision mechanical drive in the foreground, navy and warm orange palette, a quiet dark lower area for typography, no text, logos, flags or identifiable real project. It is a generated concept, not documentary evidence of an MG project.

The original MG Group SVG is composited without redrawing its geometry. Arabic shaping and English typography are rendered by Chromium from editable `design/social-card.html` using the site's bundled fonts. Every card visibly says “GENERATED CONCEPT”. The original full-resolution generation is preserved in the private production folder. The original tool response remains in the task history; the brief above documents intent rather than reproducing tool metadata.

Rebuild icons: `npm run assets:icons`. Rebuild cards: `npm run assets:social` using an existing dedicated CDP browser and Playwright; the script does not launch or shut down the browser process. `PLAYWRIGHT_MODULE` and `CDP_URL` may point to another approved local runtime. No card generation runs in CI.

## Icon package

- Adaptive vector favicon, with a light/dark background and a contrasting MG mark.
- Multi-frame ICO: 16, 24, 32, 48 and 64 px; PNG alternatives: 16, 32, 48 and 96 px.
- Opaque Apple touch icons: 152, 167 and 180 px.
- Android/application icons: 192 and 512 px, plus separate maskable variants whose mark stays within the central safe circle.
- Monochrome Safari pinned-tab SVG and legacy Windows tile assets/configuration.
- A scoped web manifest with `/mg-group/` as identity, start URL and scope; no offline capability or service-worker support is claimed.

The favicon geometry comes directly from `public/brand/mg-group-mark.svg`; it is not generated by an image model. The shared host's root favicon is deliberately not replaced: Google Search supports a favicon per hostname, not a separate search-result favicon for each subdirectory. Browser tabs and home-screen icons use the MG page's explicit icon links.

## Checks and practical limits

`npm run check:export` includes `scripts/check-seo.mjs`: it reads the built HTML and verifies metadata uniqueness, canonical URL, image URLs/dimensions/byte budgets, JSON-LD references and claims, navigation targets, sitemap, manifest scope, icon files and every ICO frame. The custom 404 stays noindex.

Browser QA covers desktop/mobile navigation, metadata hydration and SVG theme adaptation. A 320px central-square crop and a reduced landscape preview are inspected as layout stress tests, not as exact messenger screenshots. Public delivery checks request the page with representative Google, Bing, WhatsApp, Telegram, Facebook, Twitter, Slack and Discord user agents; this verifies delivery to those request profiles, not execution by their real services.

Sharing apps decide whether to show a preview, which image to select, and how long to cache it. OG and Twitter tags cover the shared discovery standards; there is no universal tag that forces every messenger to refresh or display a card. Actual native app previews, search indexing/ranking, Search Console ownership/submission and native Arabic copy review remain separate checks. No messages are sent to contacts as part of this task.
